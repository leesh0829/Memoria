# Memoria v0.13.0 Implementation Plan

**Goal:** 주간보고 들여쓰기를 탭당 공백 2칸으로 줄이고, 일일업무일지의 세 번째 후임 작업 구역을 업무내역에 연결하며, 스크롤바 조작으로 항목이 이동하는 문제를 수정한다.

**Architecture:** 기존 WPF/MVVM과 SQLite 저장 구조를 유지한다. 후임 작업은 `ItemKind.Handoff`로 저장하고 보고서 집계 전에 제외한다. 업무내역을 열 때 원본 후임 항목의 내용·고객사·완료·날짜를 안정된 식별자로 동기화하며 업무내역의 원인·조치·담당자 등 추가 정보는 보존한다. 삭제/휴지통/복원도 반영한다. 목록 드래그는 실제 항목에서 시작한 제스처에만 허용한다.

**Tech Stack:** .NET 9, WPF, CommunityToolkit.Mvvm, SQLite/Dapper, xUnit.

## Global Constraints

- 사용자가 세 항목 수정과 버전 업을 승인했다. 추가 승인 없이 현재 브랜치에 변경을 커밋·푸시한다.
- 기존 사용자 변경 `AGENTS.md`는 커밋에 포함하지 않는다.
- WPF 앱과 테스트는 Windows 전용이다. WSL에서 실행하거나 Windows 실행 파일을 호출하지 않는다.
- 최종 Windows 검증·설치는 관리자 PowerShell에서 `scripts/Install-Memoria.ps1`로 수행한다.

## Review Focus

- 후임 항목이 이슈로 잘못 집계되지 않을 것.
- 업무내역 재진입 시 중복 없이 수정 내용을 반영하고 추가 입력 정보는 보존할 것.
- 원본 삭제·휴지통 이동·복원·ID 재사용을 구분할 것.
- 이전 탭 설정/편집본과 새 공백 기반 설명 줄도 C 변환에서 처리할 것.
- 스크롤바·Thumb·버튼·빈 공간에서 시작한 이동은 재정렬이나 선택 해제를 일으키지 않을 것.
