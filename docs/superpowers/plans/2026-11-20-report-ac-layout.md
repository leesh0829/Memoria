# Report A/C layout implementation plan

**Goal:** 사용자 예시처럼 A/C 주간보고의 서식만 변경하고 업무 내용·고객사 분류·집계 기간을 유지한다.

**Architecture:** A는 고객사별 `■ 고객사 — N건 (완료 N건)` 머리글을 사용한다. C는 기존처럼 업무 고객사 머리글을 생략하되 같은 날짜·설명·이슈·일정 서식을 사용한다. 공통 출력 도우미에서 업무 괄호 표기와 비업무 구역을 렌더한다. 편집된 A에서 C로 전환할 때 직접 쓴 하위 설명이 평탄화되지 않도록 한다.

**Constraints:** 기존 WPF/.NET 9 구조 유지. WSL에서 Windows 빌드·테스트·실행은 하지 않는다. v0.14.0 코드·테스트·CHANGELOG를 현재 브랜치에 커밋·일반 푸시하고 설치 스크립트로 Windows 검증을 인계한다. 사용자 AGENTS.md 변경은 포함하지 않는다.

## Decisions

- 순서: `[업무 내용]`, `[이슈]`, `[일정]`. 각 구역 머리글 아래 빈 줄.
- A 고객사 순서와 작업 중복 병합·완료 건수 필터는 기존 기준 유지. 본문 업무는 최상위 `-`, 상세는 공백 2칸 `-`.
- 완료 `(MM/dd 완료)`, 진행 `(MM/dd~)`, 날짜 없음 `--/--`. 후행 `[디지트랙]` 등 표기는 괄호 앞부분에 병합한다.
- 자동 생성하던 빈 `o` 설명은 제거하고 실제 작성된 상세만 유지한다.
- 일정 분리는 기존 이슈에 적은 연차·출장·외근·교육/강의 등 개인 일정을 대상으로 한다. 서버 이전 지연·작업 일정 협의·출장비 정산은 이슈에 유지한다.
- B/D의 서식과 일일업무일지·후임 작업 저장 방식은 변경하지 않는다.

## Review focus

- 고객사가 다른 동일 업무와 완료/진행 혼합, 미분류·삭제된 고객사.
- A→C에서 신규 하위 `  - 설명` 보존, 이전 `o 설명`·Windows 줄바꿈·사용자 머리글 보존.
- 출장비 청구를 출장 일정으로 오분류하거나 작업 일정 협의를 개인 일정으로 옮기지 않을 것.
- 날짜가 없는/잘못된 날짜 문구나 대괄호 기술 표기를 임의로 삭제하지 않을 것.
- 양식 B/D와 후임 업무 제외 기준을 유지할 것.
